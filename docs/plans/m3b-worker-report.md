## Behavioral notes

- **Header search:** typing a query and pressing Enter submits the `<form>`,
  which calls `router.push("/search?q=" + encodeURIComponent(query))`. No page
  reload. Works on both desktop and mobile search inputs.
- **Cart badge:** `useCartStore.itemCount` drives a red `bg-[#FF3F6C]` badge on
  the Bag icon (desktop + mobile) when count > 0. `refreshCart()` runs in a
  Header `useEffect` on mount so the badge reflects an existing persisted cart.
- **PDP add-to-cart:** now uses the zustand cart store (`setCart`) so the badge
  updates immediately, and mirrors the cart id to the legacy `cart_id`
  localStorage key so the cart/checkout pages (which still read `cart_id`) keep
  working. Falls back to `cart_id` if the store's cartId is empty, to reuse an
  existing cart instead of creating a duplicate.
- **PDP wishlist:** heart button calls `addToWishlist(product.id, selectedVariant?.id)`
  + `toast.success("Added to wishlist")` when authenticated; otherwise
  `toast("Please log in to save to wishlist")` (no redirect). Auth state read
  from `useAuthStore.isAuthenticated`.
- **PDP reviews:** `getProductReviews(product.id)` on mount; shows
  `average_rating` (or derives it from returned reviews), review count, a
  per-star breakdown, and the first 3 reviews. Falls back to "No reviews yet"
  if the API fails or returns nothing.
- **PDP price:** now uses `formatPriceRupees(currentPrice)` (rupees →
  `₹{toLocaleString en-IN}`), identical to ProductCard's display for the same
  product.
- **Collection link:** `/collections/{handle}` when `product.collection.handle`
  exists, else `/products`. No `/collections` route is created; if a handle
  exists it resolves to the styled 404 (acceptable per the task).

## Image-migration caveats

- The PDP main image was previously `w-full h-auto object-contain` (height
  driven by the image's natural aspect). To use `next/image` `fill` without
  layout shift, the container is now `aspect-[3/4]` with `object-contain`
  (letterboxed within the portrait box). This is a minor container-shape change
  but no layout shift occurs (fixed aspect). Myntra product imagery is portrait,
  so this matches the expected proportion.
- Remote placeholder Myntra URLs are kept per §6.3. If a remote image fails to
  load, `next/image` shows the alt text / empty container; the explicit
  "Product Image" text fallback still renders when no image URL is present.
- Runtime image loading against the real `assets.myntassets.com` /
  `constant.myntassets.com` hosts needs browser verification (build-time the
  images are not fetched).

## Assumptions

- The Medusa v2 reviews store route (`GET /store/reviews/:product_id`) returns
  `{ reviews, total, average_rating }` per the M2 plan. The TS type was widened
  to `average_rating?: number` to match; the PDP also derives an average from
  returned reviews as a fallback.
- `MedusaCollection` may carry a `handle` (added as optional) — Medusa v2
  collections have handles; the storefront type previously omitted it.
- The cart/checkout pages still use the legacy `localStorage "cart_id"` key
  (M3a wired them that way). M3b did not migrate those pages onto the zustand
  store; instead the PDP mirrors the cart id to `cart_id` to avoid a regression.
  Fully migrating cart/checkout onto the store is a future cleanup.
